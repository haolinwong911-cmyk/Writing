# 少年新知｜新闻音频制作 Skill

当用户要求制作《少年新知》的当日/指定日期新闻内容、筛选新闻、改写口播稿或整理栏目生产日志时使用。目标是做成孩子愿意听、事实可靠、能听懂并能复述的新闻延展音频，不是新闻标题摘要或成人播报。

## 不可妥协的栏目要求

- **受众**：中国小学四至六年级学生。语言自然、平等，不幼稚化；解释必要概念，避免成人化术语、过多数据、说教和应试素材腔。
- **内容范围**：科技、文化、历史、社会、经济、航天、生命、文明、地理等。它们是可选领域，不要求每天覆盖所有领域，也不能为覆盖而硬凑。
- **长度**：目标 3–5 分钟；通常约 450–700 个汉字，实际以 TTS 试听时长为准。单篇聚焦一个新闻主题和一个核心问题。
- **事实来源**：仅以中国官方媒体网站公开发布的信息为新闻事实来源。优先回到报道首发页面核验；可用新华社/新华网、人民日报/人民网、央视网/央视新闻、中国新闻网/中新社、光明网/光明日报、中国青年报/中青报等，以及经核实的中央或地方主流媒体官网、政府部门、科研机构官网。来源范围不是要求每家都使用；来源须多样，不能习惯性只用新华社。不要以自媒体、论坛、社交平台或门户转载作为事实依据。公开可读不代表获得转载、配音或商业分发授权；独立改写并留出处，发布前遵守版权要求。
- **三种内容维度**（不是按星期排期）：
  - **世界进行时**：世界正在发生什么；交代事件及与孩子/世界的联系。
  - **新闻深一度**：从一件生活或社会中的事向下挖；理清背景、经过、原因与影响。
  - **新知超链接**：由热点连接到一个有据可查的历史、科学、人文、地理等知识。
  一篇可以选一种或组合，但不能为了贴栏目标签硬套。
- **正文形式**：必须是连贯自然的单篇口播文章，不在 TTS 正文中出现“开场钩子”“新闻事实”“解释延展”“收尾互动”等编辑小标题、分段标题或提示语。来源、链接、编辑备注放 YAML 元数据或独立日志；用户明确要求不在文末口播来源时，不得在口播尾部加来源句。

## 选题编辑规则（先筛，再写）

制作时间长时仍须先做整批筛选，禁止遇到第一条新闻就直接加工。每天/每个指定日期先建立候选池，再比较和决定入选稿件。建议扫描 50–100 条资讯；只有实际检索、记录到相应数量时才可声称完成。若资源或可检索信息不足，记录真实数量和范围，不虚报。

### 儿童适配与故事感

优先选择孩子容易想象、愿意追问，并能联系日常生活/兴趣的内容，例如运动比赛、动物、太空探索、校园体验、食物/交通/实用科技、奇特发现和有人物行动的真实故事。先找新闻中真实的“谁/什么遇到什么问题或变化，如何应对，结果/新问题是什么”，再决定是否值得讲。

以下选题原则上淘汰：缺少具体场景、人物、物件或问题；与儿童日常/兴趣缺乏联系；只能泛泛称“有意义/提升素养”；纯会议、口号、宏观经济数字、抽象政策；无可靠延展；事实不完整或不适合儿童。比如单纯讲一处水域或古迹数字化，若没有鲜活人物、具体问题和儿童可感知入口，不选。不要照搬用户举例作为固定禁题；若有新的、显著不同且适龄的事实角度，可以重新评估。

### 去重

筛选前查看本次任务涉及日期附近已产出的稿件，以及用户提供的历史主题。按地点、新闻事件、核心知识点三层检查重复，不能只比较标题。原则上不在相邻日期反复讲同一地点/事件；只有新闻事实有明显新进展，或儿童视角/解释维度显著不同且确有价值时才可重做，并在日志说明差异。不得为了数量重写旧主题、仅换标题或换比喻。

### 筛选评分

对候选以 5 项各 0–2 分快速评估：
1. 儿童好奇心：是否有反常识点、可见行动/对象或悬念？
2. 生活/认知关联：孩子能否理解为何值得听？
3. 故事性：能否根据事实讲清起因—变化/行动—结果？
4. 延展性：能否可靠解释一个知识点或引出思考？
5. 可靠与适龄：官方来源是否足够清楚，是否安全适宜？

总分低于 7/10 通常淘汰。分数是编辑辅助，不可替代判断；来源不可靠、事实不全或儿童不适宜，无论总分均淘汰。遇灾害、伤亡、暴力、犯罪、健康安全、争议政治等敏感议题，谨慎选择，必要时不做并加强核验。

每日必须完成 5–10 篇。若首轮检索合格选题不足，必须扩大官方媒体、栏目和主题范围继续筛选；仍不足时，须明确报告缺口并暂停交付，不得用旧题目改写、重复事件或编造内容凑数。

## 新闻核验与稿件编写

1. **先看报道，不凭标题写作。** 对每个入选选题保存原文链接、媒体、发布日期、事件发生日期（若不同需区分）、关键事实和限定条件。重要数字、人物、地点、状态至少回到可访问的原文核查；重要或易变化事实尽可能用第二个官方来源交叉确认。转载稿追溯首发，避免同一通稿多个转载被算作多个独立来源。
2. **拆事实层次。** 清楚区分报道确认的事实、背景知识、推论和未知；不虚构人物对话、内心活动、冲突或因果。不得把尚待审核/研究的结果说成最终定论。遇到“可能、预计、计划、首次、最大、纪录”等限定词应准确保留。
3. **搭故事，不编故事。** 用一个孩子熟悉的问题、具体画面或真实的反常识细节开场；依报道证据推进事件；再解释一个核心知识点，最后回扣开场并留一个可讨论的问题。悬念必须真实且不误导。场景化不等于虚构；类比需说明它只在哪一点相似，不能当作事实。
4. **控制认知负荷。** 短句、口语化、少量新术语；数据只留帮助理解的数字，必要时给直观参照但保留原始口径；不把解释扩成百科讲座。每一段都应推进故事或解释，确保孩子听后能用一句话复述。
5. **TTS正文干净。** 不含分段标题、栏目说明、编辑备注、来源文末尾注、Markdown 表格、括号中的制作提示。可使用自然段，但避免小标题。用户特别说明来源只供制作端核验时，来源只写 frontmatter/日志，不口播。
6. **自检。** 前15秒是否让孩子知道为何值得听？有无清晰对象、变化和核心问题？听完能否复述？有没有无来源细节、成人词、重复内容、空泛说教或信息堆叠？若不合格，应重选或重写，而不是靠音效掩饰。

## 每日选题筛选日志（必需交付）

每个日期文件夹中，除逐字稿外必须保存一份 `选题筛选记录.md`。日志要反映真实过程，不得只事后列入选稿，也不能伪造候选数量。至少包含：

- 日期和检索范围；实际查看的媒体、栏目/页面、来源链接；
- 实际查看的候选资讯数量（明确统计口径；同稿转载合并，不重复计数）；
- 候选标题、媒体/链接、领域和简要判断，或可追溯的候选清单；
- 入选主题、评分/适龄理由、对应核心角度；
- 淘汰/暂缓主题及主要理由，尤其说明无聊、儿童关联弱、重复、来源不足等；
- 与近期稿件的去重检查，若重做同地/同事，明确新增事实和差异价值；
- 当日领域分布、未覆盖领域及是否因没有合格新闻而留空；
- 最终篇数。若不到5篇，解释筛选不足，不得硬凑。

建议按 5 项评分简表呈现入选/重点淘汰项目。每日确实扫描不到 50–100 条时，写明真实数量、受限原因和采集媒体范围；后续不能把建议目标描述成已完成事实。日志要帮助复盘选题质量，也便于发现重复。

## 保存方式与文件组织

用户给了目标路径时按其路径；未指定时先确认保存位置和日期。不要擅自清空或覆盖现有稿件。优先采用：

```text
少年新知/
└── YYYYMMDD/
    ├── 选题筛选记录.md
    ├── 主题一.md
    └── 主题二.md
```

每篇稿件使用简洁 frontmatter，例如：

```yaml
---
title: "稿件标题"
date: YYYY-MM-DD
领域: "科技"
栏目维度: "新知超链接"
来源: "媒体名称"
source_url: "原文链接"
---
```

元数据不进入 TTS 正文。文件名使用日期文件夹内可读的主题名；同日不重名。完成后检查每个目标日期稿件数量、日志是否存在、来源链接和正文格式。

## 音频生成（用户要求音频时执行）

- 使用 Edge TTS 制作音频时，不预先指定音色。先询问使用者希望的声音特征，并提供可用音色供其选择；使用者已在当前任务明确选择音色时直接沿用，不重复询问。可用 `edge-tts --list-voices` 查看实际音色，例如 `zh-CN-YunxiaNeural` 是可选项之一，不是默认值。根据用户意愿提供试听；确认音色后再批量生成。语速、音高以用户指定为准，未指定可先用正常语速和默认音高。
- Edge TTS 需要联网，会将口播正文发送至微软语音服务；使用前确认文本适合发送到该服务。若需离线或用户要求其他供应商，则采用用户指定方案。对正式商用或公开发布，应核对所用服务的最新使用条款及权限。
- 先检查是否已安装：`edge-tts --version`；如不可用，在合适的 Python 虚拟环境中执行 `python -m pip install edge-tts`。本次已使用的虚拟环境为 `/Users/haolinwong/Documents/Codex/2026-11-04/new-chat-4/work/chattts/venv/`；路径可能随工作环境变化，使用前检查，不可假定始终存在。
- 逐篇从 Markdown 提取口播正文，排除 YAML frontmatter、标题、来源链接、编辑提示及 `选题筛选记录.md`。如有疑问先检查原稿结构，不要删除正文；必要的数字和专名读法先进行口播文本规范化。示例（`正文.txt` 为已清理的 UTF-8 正文）：

  ```bash
  edge-tts --voice "用户选择的音色ID" \
    --file 正文.txt --write-media 主题.mp3
  ```

- 默认按日期分别存入 `少年新知/YYYYMMDD/音频/主题.mp3`，与逐字稿同名；用户另指定位置时遵照指定。批量前先清点目标稿件和已有文件，不得覆盖已有音频，除非用户明确要求重制。临时文件放工作目录并清理；逐篇失败时记录并重试，服务异常不把空文件当成功。
- 完成后逐日期核对稿件与音频一一对应，检查 MP3 可解码、时长和文件大小，并按下方要求试听检查；不以文件数量代替播放质量检查。网络失败或未经试听时如实说明。
- 采用清晰、亲切、不幼态化的普通话音色；语速适中，停顿自然，少量重音，不用夸张情绪。
- 片头短且稳定；音效/音乐克制，不遮盖人声或制造不必要紧张。正文严格使用无编辑标题的稿件文本。
- 生成后核查时长、发音、数字与专名、静音/截断、音量，并试听全片或至少逐篇抽检关键段。需改读音时先更新读音词典/文本，再重制。
- 不默认假设孩子喜欢某种声音或音效；依据收听、完播、退出点、复述/追问和家长反馈迭代。

## 按任务类型执行

- **制作指定日期内容**：核对日期范围、历史稿件去重 → 多站候选检索 → 记录真实候选池 → 评分筛选 → 原文事实核验 → 连续口播稿 → 每日日志 → 保存并检查。
- **只改一篇稿子**：遵守事实与TTS格式，不必重新执行每日50–100候选流程；如改动影响选题/事实结论，同步更新对应日志。
- **只讨论方案/规则**：不擅自生成新闻稿或音频；把建议和已确认要求区分清楚。
- **遇到关键缺项**：先向用户逐步确认会实质改变工作的事项（例如日期、目标路径、是否需要音频文件）；不要一次抛出无关问题。其余按本技能和已有约定合理执行。

## 用户偏好（累积约定）

- 以编辑思维先筛新闻，再动笔；儿童兴趣与故事性优先，不为新闻数量或领域覆盖牺牲质量。
- 规避短期重复，允许有充分差异价值的回访；对桂林水、古迹数字化等欠缺儿童日常入口、容易讲得抽象的选题尤其谨慎。
- 每日逐字稿数量要求为 5–10 篇；交付前必须核对数量，不足5篇不得宣称完成，须继续补充筛选或向用户报告阻塞原因。
- TTS稿不要分段标题；来源信息不放口播末尾，除非用户后来明确要求。
- 来源应覆盖多个国内主流官方媒体网站；不因新华社方便就长期单一依赖。来源数量、候选数量均如实报告。
