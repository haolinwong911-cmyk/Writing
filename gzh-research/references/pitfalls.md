# 踩坑与解法清单（gzh-research）

> 这些是实跑中真实遇到并解决的问题，固化下来避免重蹈覆辙。

## 1. 小绿书没有 `#js_content`（最关键，最初就在这里栽了）
- 现象：一批文章抓下来“正文为空/过短”，但页面有 2MB+、标题正常。
- 根因：小绿书/图片消息的正文**不在** `#js_content`（普通图文才有），而是：
  - 文字型 → 藏在页面 JS 的 `content: '...'` 字段（HTML 被转义为 `\x3c`/`\x3e`/`\x0a`/`\x22`）；
  - 纯图片型 → `content` 为空，正文是图片序列，图片地址在 `cdn_url: '...'`。
- 解法：解析顺序 = `#js_content` → JS `content` 字段(反转义) → `cdn_url` 图片列表。三段兜底，见 `scripts/scrape_content.py::extract`。
- 判别技巧：普通文章页 ~3.5MB 且有 `#js_content`；小绿书 ~2.2MB 无 `#js_content`。

## 2. 微信风控是 IP 级，验证页长什么样
- 触发：高频直抓（尤其带大量重试）会触发微信风险控制。
- 验证页特征：体量骤降到 ~17KB、含 `secitptpage/verify*.css`、无 `#js_content`、body 只有“微信扫一扫/使用小程序”外壳。
- 解法：① 限速 ≥1 秒/篇；② 风控后**静置冷却**一段时间会自愈（分钟到小时级）；③ 本环境出口 IP 固定（走本地代理 `127.0.0.1`，如 63637），无 VPN/代理池可切换——换 IP 需用户侧解决（手机热点/代理）。
- 注意：风控是暂时的，同一批文章冷却后重抓往往就能成功，别急着判定“已删除”。

## 3. history 翻页去重要按“标题”，不是按 URL
- 现象：翻页尾部混入最近文章的重复项，数量虚高。
- 根因：重复项的 `content_url` 因微信 `sessionid` 参数不同而**不同**，按 `content_url` 去重完全无效。
- 解法：按**标题归一化**去重（去空白、去内联 HTML 标签、取前 ~40 字）。

## 4. data2 字段名反直觉
- `read_num`=阅读量、`old_like_num`=**点赞**、`like_num`=**在看**（不是点赞！）、`comment_count`=评论数、`share_num`=分享数。
- 把 `like_num` 当点赞会全表列错。已在 `build_report.py` 按正确列映射。

## 5. 匹配已存 .md 用“文件名序号前缀”，别用 source 链接
- 现象：个别文章标题里含 `<a class="...">` 标签和换行，会把 front matter 的 `title:` 撑成多行、把 `source:` 行顶到很后面，导致“按 source 链接反查文件名”漏判（明明存了却显示未抓）。
- 解法：用文件名序号前缀 `NNN_` 匹配（`build_report.py` 即如此）；同时 `safe_name` 清理标题里的标签/控制字符。

## 6. 余额差一点会缺末尾几篇
- data2 跑大量时，若 余额 < 篇数×单价，末尾几篇会因 `6020` 取不到。跑前先算 余额 vs 篇数×0.03，差几篇提前告知用户，由其决定充值或接受缺失。接口到 0 即停，不会超扣。

## 7. 后台跑脚本务必带凭证环境变量
- `APP_ID`/`APP_SECRET` 用环境变量传入；后台启动若漏带，脚本 `KeyError` 秒退（好处是没有任何花费）。命令形如：
  `APP_ID=xxx APP_SECRET=xxx python fetch_metrics.py`

## 8. 直抓正文的小细节
- 请求带浏览器 UA + `Referer: https://mp.weixin.qq.com/`；图片是懒加载，取 `data-src` 不是 `src`。
- 发布时间用 history 接口返回的 `published_at`，别用页面 `var ct`（省去时区换算，ct 是秒级时间戳、口径易混）。
- 断点续传：用 `_progress.json`（正文）/ `_metrics.json`（指标）记录已完成的 URL，重跑自动跳过，避免重复付费。

## 9. 失败重试的“计费与否”边界
- 不计费可重试：`6021`/`5300`/`1004`(等30秒)/`429`/`1003`。
- `6020` 余额不足：接口未执行、不计费，应停止并让用户充值，别反复重试。
- 重复调用成功接口=重复付费，别用计费接口做轮询。
