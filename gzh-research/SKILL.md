# 微信公众号全量采集与存档

## 概述
把一个公众号的全部历史文章抓下来、存成 Markdown、并汇总成带「内容分类 / 类型 / 阅读·点赞·在看·评论·分享」的表格。
- **wxid 提取**：用一篇文章链接**免费**直提（不走付费接口）。
- **次幂数据(cimidata)付费 API**：取发文列表、取互动指标（按次计费）。
- **免登录直抓 mp.weixin.qq.com**：取文章正文（**免费**，但必须区分普通图文与小绿书两种结构）。

## 依赖（自包含，别人拿去即可跑）
- 自带次幂 API 客户端 `scripts/cimi_client.py`（token/历史列表/互动指标/余额，限速+重试+断点续传），**无需再装其它 skill**。
- 运行环境：Python 3 + `requests` + `beautifulsoup4` + `lxml`（xlsx 还需 `openpyxl`）。
- 目录：`SKILL.md`(主指南) / `README.md`(用法) / `scripts/`(cimi_client.py、scrape_content.py、build_report.py) / `references/`(pitfalls.md、cimi_quickref.md)。

## 执行总流程（顺序固定）
**步骤0 免费提 wxid → 步骤1 要次幂凭证 → 步骤2 取历史列表(付费) → 步骤3 下正文(免费) → 步骤4 取指标(付费,可选) → 步骤5 汇总成表(免费)**。
收费的只有步骤2、4；且都必须在执行前按下面的“三段式”向用户报价并取得同意。

## 报价三段式（每个付费步骤都必须按此格式，别吓到用户）
```
1、执行的逻辑：<调用哪个接口、翻页/逐篇怎么跑、大概调多少次>
2、收费标准：<单价、计费单位(每页/每篇)、失败是否计费>
3、这次预计执行要花多少钱：<约 N 次 × 单价 = X 元；附 300篇/500篇 算例；当前余额够不够>
```
规则：先查余额(`GET /api/v2/user/balance`，免费)再报价；**用户同意才执行**；执行中若发现将超出已确认预算，立即停止并再次确认，不擅自超花。失败/限流(`6021/5300/1004/429/1003`)不计费可重试；`6020`=余额不足(未执行、不计费)，应停止让用户充值。

**余额判读**：`balance` 单位是**分**（÷100 = 元）。若返回 **≤0 或 -1**，说明余额已耗尽/被扣成负值，须先告诉用户“余额不足/已用完，请去 cimidata.com 充值”，不要硬跑（到 0 接口会自动停且不计费，但会白跑一趟）。余额正常时按 `balance/100` 报“当前余额 X 元”。

## 步骤0：先要一条文章链接，免费提取 wxid（不走付费接口）
- 向用户要目标公众号的**任意一篇文章链接**（形如 `https://mp.weixin.qq.com/s?__biz=...&mid=...`）。**明确告诉用户：本步免费**，只用它提取 wxid，不调用次幂、不花钱。
- 提取方法：GET 该链接，在页面里搜 `var user_name`，取 `gh_` 开头的字符串即为 wxid（可用文章页 `__biz` 参数辅助校验）。用户也可直接提供 wxid，跳过本步。
- 拿到 wxid 后才进入下一步。

## 步骤1：索取次幂凭证
引导用户按固定块提供，并告知注册位置：
```
app_id:        （次幂用户名）
app_secret:    （次幂密钥）
```
- 注册：https://www.cimidata.com 注册登录 → https://www.cimidata.com/api-service 开通 API 服务并创建 app_id/密钥。
- 安全：凭证只走环境变量 `APP_ID`/`APP_SECRET`，**绝不写死进 .py/.json/日志**；后台跑必须显式传环境变量，否则 `KeyError` 秒退。

## 步骤2：取历史发文列表（付费）——三段式报价
向用户这样说：
```
1、执行的逻辑：调用 /api/v2/articles/history，每页约 10 篇，用 last_id 翻页取全；
2、收费标准：0.05 元/页（约10篇/页，折合约 0.005 元/篇）；失败/限流不计费；
3、这次预计执行要花多少钱：约 页数×0.05。参考：300篇≈30页≈1.5元；500篇≈50页≈2.5元
   （篇数为估算，以实际翻页为准）。当前余额 X 元，[够/不够]。
```
同意后执行：`python scripts/cimi_client.py history <wxid> articles.json`。
**去重坑**：翻页尾部会混入最近文章的重复项，且这些重复项 URL 因微信 `sessionid` 参数不同而不同，按 `content_url` 去重无效——必须按**标题归一化**去重（`scrape_content.py` 已内置）。

## 步骤3：下载正文（免费，不走付费接口）——也要讲清逻辑与"次数"
向用户这样说（三段式，费用为 0）：
```
1、执行的逻辑：对 articles.json 里每篇文章的公网链接直接 GET，解析正文、每篇存一个 .md；
2、收费标准：免费——直连 mp.weixin.qq.com 公网，不调用次幂、不按篇计费；
3、这次预计执行要花多少钱：0 元。约 N 篇直连请求（普通文章、图文/小绿书都算一篇），只花时间不花钱。
```
执行：`python scripts/scrape_content.py articles.json ./文章存档 --sleep 1.0`。
三种结构解析（关键）：① 普通图文文章→`#js_content`；② 文字型小绿书→页面 JS 的 `content:'...'` 字段(反转义)；③ 纯图片小绿书→`cdn_url` 图片序列存成 `![]()`。标题取 `og:title`，发布时间用步骤2的 `published_at`，图片取 `data-src`。限速≥1s/篇防风控，`_progress.json` 断点续传。

## 步骤4：取互动指标（付费，可选）——三段式报价
向用户这样说：
```
1、执行的逻辑：对每篇文章调 /api/v2/articles/data2，取 阅读/点赞/在看/评论/分享；
2、收费标准：0.03 元/篇；失败(6021等)不计费；
3、这次预计执行要花多少钱：约 N篇×0.03。参考：300篇≈9元；500篇≈15元。当前余额 X 元。
```
字段映射（**命名反直觉**）：`read_num`=阅读、`old_like_num`=点赞、`like_num`=在看、`comment_count`=评论、`share_num`=分享。
同意后执行：`python scripts/cimi_client.py data2 articles.json metrics.json`（实时监控 `balance`，`6020` 即停，断点续传）。用户只想存正文可跳过本步。

## 步骤5：汇总成表（免费）
执行：`python scripts/build_report.py articles.json ./文章存档 [metrics.json] -o 汇总表`。
列：序号/发布时间/标题/内容分类/类型(文章·图文)/访问链接/是否抓取到/阅读量/点赞/在看数/评论数/分享数/存档位置。
**匹配已存 .md 用“文件名序号前缀(NNN_)”**，别用 front matter 的 source 链接（标题含 HTML/换行会撑破 front matter 导致漏判）。内容分类为多标签（逗号分隔）：接广告/产品测评/干货教程/产品发布/资讯观点/周刊合集/个人随笔/其他，启发式、边界样例可能需人工复核。

## 关键坑速查（详见 references/pitfalls.md）
1. **小绿书无 `#js_content`**——只认 `#js_content` 会把整批小绿书判“正文为空”；必须按 content 字段 / cdn_url 兜底。
2. **微信风控是 IP 级**——高频直抓返回验证页(`secitptpage/verify*.css`、约17KB、无正文)；限速≥1s/篇 + 静置冷却自愈。
3. **余额差一点会缺末尾几篇**——data2 跑大量时，先算 余额 vs 篇数×0.03。
4. **去重按标题、匹配按文件名前缀**。
5. **后台脚本必带 APP_ID/APP_SECRET 环境变量**。
6. **批量替换文件内容别用 `open(p,'w').write(open(p).read()...)`**（'w' 先清空再读会截断文件）；先 read() 进变量再写。
