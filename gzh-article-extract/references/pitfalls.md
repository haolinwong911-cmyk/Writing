# 踩坑与解法清单（公众号文章爬取）

## 1. 小绿书没有 `#js_content`（最大的坑）
微信的“图片消息/小绿书”页面**没有** `#js_content` 节点。如果解析器只认这一个节点，会把所有小绿书判为“正文为空”。
实际有三种形态，必须按顺序兜底：
1. **普通图文文章**：`#js_content` 服务端渲染，直接解析。
2. **文字型小绿书**：正文藏在页面 JS 的 `content: '...'` 字符串里，带 `\xHH`（如 `\x3c` = `<`）、`\n`、`\"` 等转义。要先取出这个字符串、逐字符反转义，再当 HTML 解析。注意页面里可能有多个 `xxx: '...'` 字段，**取最长的那一个**。
3. **纯图片小绿书**：`content` 字段为空，正文就是图片序列。提取所有 `cdn_url: '...'`，按出现顺序去重，存成 `![](url)` 列表，并在文首加一句说明（“本文为小绿书/图片消息，正文由以下图片构成”），避免读者误以为抓漏了。

## 2. 图片地址在 `data-src`，不在 `src`
微信文章图片全部懒加载：HTML 里的 `src` 是占位符，真实地址在 `data-src`。解析时优先取 `data-src`，`src` 只作兜底。

## 3. 微信风控是 IP 级的（失败≠删除）
高频直抓（尤其是批量重试）会触发微信风控，返回一个**验证页**：
- 体积很小（约 17KB）；
- 没有 `#js_content`；
- HTML 里含 `secitptage` / `verify*.css` / “验证”字样。

**这不是文章被删除**，是出口 IP 被临时限流。特性：
- 静置一段时间（10~30 分钟以上）会自愈；
- 越频繁重试，冷却越久；
- 换网络/代理可立即绕过。

所以脚本对“三种结构都没抓到”的情况，会先检查删除标记（“该内容已被发布者删除”等），再检查风控特征，给出不同错误信息。**遇到风控就停，别连着重试。**

## 4. 时间提取的多个位置
发布时间没有统一字段，按可靠性排序：
1. `var ct="1699999999"`（unix 秒，最常见）——用 `datetime.fromtimestamp` 转本地时间；
2. `create_time` / `publish_time`（可能是 unix 秒或 `'YYYY-MM-DD HH:MM:SS'` 字符串）；
3. 都没有就留空，文件名省略日期前缀（别瞎编时间）。

## 5. 公众号名在四种位置
1. `#js_name` 节点（普通文章）；
2. `var nickname = '...'`（部分页面）；
3. `window.name = "..."`（小绿书）；
4. `nick_name: '...'`（小绿书页面里的 JSON 块，同块还有 `user_name: 'gh_xxx'` 即 wxid，本 skill 不用但可参考）。

## 6. 链接参数
- `?__biz=...&mid=...&idx=...&sn=...` 是核心参数，缺了会 404；
- `sessionid` / `scene` / `chksm` 等不影响抓取，可原样带着；
- 末尾的 `#rd` 是微信加的锚点，去掉也行；
- 链接过期（`expire` 参数）时会跳到验证页——按第 3 条处理。

## 7. 批量使用的纪律
- 每条之间 sleep ≥1.5s（脚本默认值）；
- 一批 ≤20 篇，批间休息几分钟；
- 要大规模采集（几百篇）不要用本 skill 硬刚，那是 `gzh-research` 的场景（它有断点续传和更完整的批量治理）。

## 8. 环境相关（本机实测）
- 出口 IP 若走本地代理（如 127.0.0.1:xxxxx），风控恢复速度取决于代理出口的纯净度；
- 依赖装不上时，确认用对 Python：`pip install beautifulsoup4 lxml requests` 后再跑。
